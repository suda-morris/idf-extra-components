# Changelog

## 0.1.0

- Initial version
- `esp_lcd_new_panel_host_sdl()` creates an `esp_lcd` panel backed by SDL: `draw_bitmap()` / `draw_bitmap_2d()` calls are stored in an internal framebuffer
- `esp_lcd_host_config_t` selects resolution, color format, preview window, preview scaling and window title per panel
- SDL3 is vendored as the `esp_lcd_host/SDL` submodule and built with the CMake project of SDL itself: `add_subdirectory()` reuses the SDL source lists and generates `SDL_build_config.h`. The port keeps video, events, threads, timer and filesystem with the software renderer, the X11 and Wayland drivers so the preview window opens on a desktop (both probed and enabled by default, both can be turned off), the KMSDRM driver when `libdrm`, `gbm` and EGL are present and the dummy and offscreen drivers everywhere else. Audio, camera, joystick, haptic, hidapi, sensor, power, dialog, tray, GPU and the GPU/board video drivers are disabled, and the optional dependencies SDL probes for (Fribidi, libthai, D-Bus, IBus, libudev, liburing) are turned off so the build does not depend on the build machine
- The component depends on `espressif/libpng` for `esp_lcd_host_screenshot_save_png()` and on ESP-IDF, and the SDL configuration in the component CMakeLists.txt is the only place to review when the SDL submodule is updated; the source lists and the build configuration come from SDL
- `idf_component_register()` requires `esp_lcd`, and the applications use the generic `esp_lcd` panel API straight from the `esp_lcd` component headers: the host fallback of the panel interface (`esp_lcd_host_types.h` and `esp_lcd_host_panel_ops.c`) was removed once `esp_lcd` built for the `linux` target
- Optional SDL preview window (`create_window`), refreshed by `esp_lcd_host_pump_events()`
- `esp_lcd_host_screenshot_save_png()` streams scanlines into a PNG file via libpng `png_write_row` (no extra full-frame RGB buffer)
- `esp_lcd_host_return_panel()` and `esp_lcd_host_return_buffers()` publish the latest frame to the SDL backend
- `esp_lcd_host_get_target()` reports whether the application runs on the host (POSIX) target or on a chip
- The component manifest restricts the component to the `linux` target, it is a host simulation only. `linux` is the name ESP-IDF gives the host target on every operating system, so the component builds on Linux, macOS and Windows: the SDL configuration reads the platform from `CMAKE_SYSTEM_NAME` and lets SDL select the window driver (X11, Wayland or KMSDRM on Linux, Cocoa on macOS, Win32 on Windows), the thread back end and the platform sources. Only the Linux desktop packages are probed, and `src/esp_lcd_host.c` no longer depends on `<sys/param.h>`
- The port no longer probes the platform itself: the pthread results, inotify, the X11 extensions, Wayland, KMSDRM, EGL and the desktop packages are all left to the SDL project of the submodule, which is what keeps the two in sync. The SDL configuration shrinks to the option list plus the few checks whose result depends on the machine rather than on the platform. The X11, Wayland and KMSDRM drivers are selected through `ESP_LCD_HOST_SDL_X11`, `ESP_LCD_HOST_SDL_WAYLAND` and `ESP_LCD_HOST_SDL_KMSDRM`, which are on by default, so it is now possible to build with only some of the desktop drivers instead of all or none
- The SDL drivers are loaded with `dlopen()` at run time (`SDL_DEPS_SHARED=ON`), which is what a desktop build of SDL does: a driver that is compiled in no longer stops the executable from running on a machine that does not have the desktop libraries, so the panel keeps working as a frame buffer there
- `src/esp_lcd_host.c` defines `MIN`/`MAX` itself instead of including `<sys/param.h>`, which MSVC does not have
- The example falls back to a framebuffer only panel when the preview window cannot be created, so it also runs on a headless machine
- The preview presents frames through an SDL streaming texture and a renderer (`SDL_UpdateTexture` + `SDL_RenderPresent` with a logical presentation size of the panel resolution). The window-surface API has no implementation in SDL's Wayland driver, so the renderer path is the one output that works on every desktop and it also scales the panel to the window size for free
- `esp_lcd_host_pump_events()` walks every SDL backend the component created instead of only draining the shared SDL event queue: it presents the dirty windows and handles the close requests, which is what makes the preview actually appear
- `esp_lcd_host_window_close_requested()` reports that the user closed a preview window (or quit from the window manager), so an application can stop its loop and exit
- The SDL backend keeps a registry of its contexts behind a mutex, so several panels can have preview windows at the same time and one `esp_lcd_host_pump_events()` refreshes all of them
- The panel `init` callback is implemented (it clears the framebuffer): `esp_lcd_panel_init()` requires it, the call used to crash; `reset` stays optional and reports `ESP_ERR_NOT_SUPPORTED`
- The SDL submodule is built only in the configuration phase passes that allow `add_subdirectory()` (`CMAKE_BUILD_EARLY_EXPANSION` guard), and the git-describe include-guard collision between ESP-IDF's and SDL's copies of `GetGitRevisionDescription.cmake` is resolved before `add_subdirectory(SDL)`
- The LVGL example opens the preview window interactively (it pumps events and stops when the user closes the window), sets the LVGL tick and delay callbacks to host sources, and keeps the headless fallback for CI, where the pytest run forces `SDL_VIDEODRIVER` to a value that disables window creation so the test is deterministic on desktops too
- The preview uploads only the union of the panel regions drawn since the last present into the streaming texture (GUIs that flush in partial areas no longer upload the whole framebuffer every pump), and the panel `init` marks the cleared power-on frame dirty so the window shows it before the first draw
- The renderer is deliberately created without vsync: SDL waits for the compositor frame callback on present, and an occluded preview window never receives one, which would stall `esp_lcd_host_pump_events()` forever. The application paces the pump loop instead
- The SDL build configuration moved from `port/sdl/CMakeLists.txt` into the component `CMakeLists.txt` and the SDL stubs moved from `port/src/sdl_port_stubs.c` to `src/sdl_port_stubs.c`: the component registers first and then adds the vendored SDL subproject, like mbedtls and the other components that vendor a CMake project. The register call seeds the directory scope with the include directories, compile options, definitions and common link libraries of the build system; that scope is snapshotted onto the component target and reset before the subdirectory is added, because the linux build compiles everything with `-Werror` and a fixed C standard that the SDL sources do not survive, and SDL exports its library, whose export may not reference the IDF targets outside its export set
- The Windows host support is removed: the ESP-IDF linux target is a POSIX simulator that runs on Linux and macOS only. The configuration rejects any other host system up front, and the README and the manifest no longer advertise Win32
